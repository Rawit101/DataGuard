## Architecture decisions retained

- SQL is one read-only SELECT/CTE over aliases from the selected project. The parser allowlist and isolated DuckDB connection also block file access and extensions.
- A single worker serializes pipeline and SQL export jobs. API reads and previews create their own DuckDB connections; connections are never shared between requests.
- CSV source bytes are retained. A record with the wrong number of columns is listed with content and reason. If CSV syntax prevents safe recovery, the unread tail is one explicit rejection. Invalid typed values stay in the accepted snapshot as raw text and appear as parse issues.
- Output is copied to a temporary managed path and entered into the artifact catalog only after successful computation and required quality gates. Failed or cancelled pipeline runs remove the temporary and final files. The app marks in-progress jobs as interrupted on restart.

## Remaining product boundaries

The local MVP supports one trusted user and one app instance per workspace. The step editor is JSON based. Interactive SQL and exact profiles can be expensive for very large data. The deterministic running-cancellation test pauses a real worker after it reaches `running`, requests cancellation through the API, and verifies termination and cleanup; direct interruption of a long DuckDB statement remains unverified in this environment. See [real-functionality-verification.md](real-functionality-verification.md) for commands and results.
